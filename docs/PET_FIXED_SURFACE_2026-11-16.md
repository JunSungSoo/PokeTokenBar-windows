# 미세 잔상 후속 점검: 고정 표면

이전 전체 재그리기 보완 후에도 미세 잔상이 남는다는 사용자 보고에 따라 Windows의 호버 크기 변경 자체를 제거했다.

## 확인 및 변경

- 이전 방식은 말풍선마다 네이티브 투명 창의 크기와 원점이 변했다. 새 방식은 `max(size,180) × (size+72)` 표면을 유지해 포켓몬의 CSS 위치·네이티브 창 위치·크기가 호버 중 변하지 않는다. 펫 크기 설정을 바꾸거나 사용자가 드래그하는 경우에는 정상적으로 변경한다.
- 말풍선이 없을 때는 Windows 창 영역을 펫 사각형으로 제한한다. 빈 위쪽/좌우 여백은 그리지 않고 뒤의 창으로 입력을 통과시킨다. 말풍선이 있을 때만 전체 영역을 허용한다. [Electron setShape 공식 API](https://www.electronjs.org/docs/latest/api/browser-window#winsetshaperects-windows-linux-experimental)를 사용한다.
- **125% 배율에서 기존 크기 되맞춤이 실제 1DIP 재배치를 일으키는 실패를 발견했다.** 175%에서도 반환된 크기와 요청한 크기가 달라 재보정하는 경로가 확인됐다. 설정한 논리 크기를 따로 기억하고, 네이티브 반올림 결과를 다시 크기 변경 요청으로 되먹이지 않도록 수정했다.
- 입력/그리기 영역은 실제 네이티브 표면 크기에 맞춰 계산하고, 가로 중앙이 소수인 경우 바깥쪽으로 반올림해 포함한다. 배율과 표면 크기가 바뀌면 영역을 다시 계산한다.
- 시각 디자인·알 이미지·GIF·기도·하트·드래그·위치 저장은 유지했다. macOS 방식의 논리 크기 계산 함수는 유지하고 Windows만 고정 표면을 사용한다.

## 검증

- 빌드/타입 검사/변경 형식 검사 통과.
- 전체 129개 중 Windows 119 통과, 실패 0. 기존 Swift/macOS 관련 10개는 제외. 이번 변경은 Windows 창과 표현 경로이며 원본 Swift 로직 변경은 없다.
- 기본 배율과 강제 렌더링 125%/175%에서 48/96/192px, 12회씩 호버 진입/이탈 검사 통과. 호버 중·후 네이티브 `setBounds` 0회, 실제 창 위치·크기 불변, 원래 정적 RGBA 픽셀 복원 확인.
- `GetWindowRgn` / `PtInRegion`으로 실제 Windows 영역을 조회해, 말풍선이 없을 때 위쪽과 좌우 빈 여백이 제외되고 펫은 포함됨을 확인했다. 말풍선 표시 중에는 위쪽 영역이 포함된다. 사용자 마우스를 움직이지 않는 읽기 전용 검사다.
- 실제 Windows 합성 캡처 6회에서 펫의 CSS 사각형 밖 잔여 픽셀 0개. 이전 검사의 2px 제외 여백을 없애고 배경색 허용 오차도 3에서 1로 줄였다. 캡처는 테스트 전용 배경 창 영역으로 제한했다.
- 테스트 창 파괴는 정상 완료됐다. 임시 Chromium 프로필 삭제의 재시도 시간을 없애 검증 종료 지연을 줄였다.
- CI에 125%/175% 펫 검증을 추가했다.

로그: `output/pet-fixed-surface-ui.log`, `pet-fixed-surface-125.log`, `pet-fixed-surface-175.log`, `pet-fixed-surface-compositor.log`, `pet-fixed-surface-tests.log`.

사용자의 미세 잔상 자체를 동일한 GPU에서 관찰한 것은 아니다. 이번에는 잔상을 유발할 수 있는 호버 재배치 경로를 제거했고, 분수 배율 재배치 실패는 테스트에서 재현해 보완했다. 실제 앱 확인 시에는 현재 실행 중인 이전 앱을 종료하고 새 폴더에서 수정본을 실행해야 한다.

## 실행 파일

기존 앱 프로세스의 ASAR를 읽어 이전 재그리기 보완은 포함돼 있지만 고정 표면/분수 배율 보완은 아직 포함되지 않은 빌드임을 확인했다. 사용자 앱은 강제 종료하거나 교체하지 않았다.

수정본은 바탕화면 `PokeTokenBar-Windows-1.0.0-x64-fixed-surface.zip`에 새 이름으로 저장했다. 최종 EXE는 격리된 설정에서 펫을 켠 상태로 시작했으며 `Desktop ready`와 오류 없는 초기화를 확인했다. 패키지 코드 26개와 ZIP 전체 76개 파일/바탕화면 사본의 해시가 일치한다.
