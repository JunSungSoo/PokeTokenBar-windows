# 플로팅 펫 호버 이탈 잔상 보완

## 원인 점검

호버 말풍선이 켜지거나 꺼질 때 펫의 투명 창이 `size×size`와 `max(size,180)×(size+72)` 사이에서 크기와 원점을 함께 바꾼다. 기존 컨트롤러는 상태만 갱신돼도 같은 좌표·크기를 `setBounds`로 다시 보냈으며, 네이티브 창 변경 직후 전체 투명 표면의 재그리기를 요청하지 않았다. 실제 계측에서 변경 없는 `sync()` 5회에 동일한 창 재배치도 5회 발생했다.

투명 창의 크기 변경과 렌더러 합성 프레임 반영 시점이 다르면 이전 표면이 잠시 남을 수 있는 경로다. 이 경로를 보완했다. 다만 이 개발 환경의 수정 전 정적 프레임/실제 Windows 합성 캡처에서는 사용자가 본 **지속 잔상** 자체는 재현되지 않았다. 따라서 특정 GPU/디스플레이 환경의 원인까지 확정한 것으로 보고하지 않는다.

## 수정

- 좌표·크기가 같은 `setBounds` 호출을 생략한다. 동일 상태 5회 갱신의 창 재배치는 수정 후 0회다.
- 크기 변경·창 표시 시 `webContents.invalidate()`로 전체를 재그린다. 32ms 후 한 번 더 요청해 크기가 바뀐 표면 반영을 보완한다. 상시 폴링은 사용하지 않는다.
- 말풍선 상태 변경과 `resize` 후 렌더러의 두 프레임을 기다려 최신 DOM 배치에서 전체 재그리기를 요청한다. 중복 요청은 합치며 창 종료 시 예약 작업을 취소한다.
- 펫 창의 배경을 명시적으로 완전 투명하게 설정하고, 펫 창의 백그라운드 스로틀링을 해제한다. 기존 GIF 품질·절전·동작 줄이기 설정은 유지한다.
- 새 IPC는 펫의 주 프레임만 허용한다. 파괴된 창 접근을 확인하고 종료 시 타이머를 해제한다.
- 정적 테스트 응답도 실제 유효한 포켓몬 PNG로 교체했다.

`invalidate()`는 [Electron 공식 API](https://www.electronjs.org/docs/latest/api/web-contents#contentsinvalidate)에 정의된 전체 재그리기 요청을 사용한다. 전역 GPU 가속 해제나 창 숨기기/다시 보이기는 적용하지 않았다.

## 검증

- 빌드, 타입 검사, 변경 형식 검사 통과.
- 전체 Windows 테스트: 127개 중 117 통과, 실패 0, 기존 Swift/macOS 관련 10개 제외. 이번 수정은 Windows 창·렌더러 경로에 한정되며 Swift 비교 로직은 변경하지 않았다.
- `scripts/pet-ui-smoke.mjs`: 같은 상태 5회에서 재배치 0회, 48/96/192px에서 12회 호버 진입/이탈 후 **원래 RGBA 픽셀 및 화면 좌표와 일치**, 크기 변경 시 전체 재그리기 호출을 확인했다. 알·기도·반복 클릭·하트·드래그도 통과했다.
- `scripts/pet-compositor-smoke.mjs`: 테스트 전용 단색 배경 위에서 실제 Windows 화면 합성을 검사했다. 저장한 캡처는 테스트 창 영역만 포함한다. 96/192px 총 6회 호버 이탈 후 펫 영역 밖 잔여 픽셀 0개. 이 검사는 로컬 실행용이며 CI에서 바탕화면 캡처를 실행하지 않는다.
- CI에는 숨겨진 펫 UI 복원/재그리기 검사를 추가했다.
- 로그: `output/pet-bounds-before.log`, `pet-ghost-before.log`, `pet-compositor-before.log`, `pet-ghost-tests.log`, `pet-ghost-after.log`, `pet-compositor-after.log`.

사용자의 GPU/배율 환경에서 지속 잔상이 재발하는지는 수정된 실행 파일로 추가 확인이 필요하다.
